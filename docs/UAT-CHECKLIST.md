## A. الحسابات والمصادقة
- [ ] تسجيل حساب جديد ينجح، وتسجيل نفس البريد مرة ثانية يعطي رسالة تعارض (409)
- [ ] تسجيل الدخول بكلمة مرور خاطئة يفشل برسالة عامة (لا تكشف هل البريد موجود)
- [ ] بعد 10 محاولات سريعة على التسجيل/الدخول يظهر تقييد المعدل (429)
- [ ] تسجيل الخروج ثم الدخول يعيد سلة المستخدم المحفوظة
- [ ] عميل عادي يفتح `/admin` → يُمنع (تحويل أو 403)، وطلب `/api/admin/*` → 401/403
- [ ] استعادة كلمة المرور تعمل من البداية للنهاية (إن كانت مفعّلة)

## B. الكتالوج والبحث
- [ ] قائمة المنتجات تحمّل مع ترقيم، وصور المنتجات تظهر
- [ ] البحث النصي والفلاتر (فئة/سعر/توفر) والترتيب تعمل معاً، والرابط يحفظ الفلاتر عند التحديث
- [ ] منتج نفد مخزونه يظهر "غير متوفر" ولا يمكن إضافته للسلة
- [ ] صفحة منتج غير موجود تعرض 404 مفهومة
- [ ] عرض المتغيرات (مثل علبة 250غ) يغيّر السعر والمخزون بشكل صحيح

## C. السلة
- [ ] إضافة/حذف/تعديل كمية، والمجموع صحيح
- [ ] سلة الزائر تُدمج مع سلة الحساب عند تسجيل الدخول (تجمع الكميات ولا تتكرر البنود)
- [ ] تغيير سعر/مخزون منتج من لوحة الإدارة ثم الذهاب للدفع → تظهر ملاحظات `CartValidationIssue` بدل طلب خاطئ

- [ ] دولة غير مدعومة في الشحن تعطي رسالة مفهومة لا خطأ 500

## E. الدفع والمخزون (الأخطر — لا إطلاق قبل نجاح كل بنوده)
لكل بوابة (Stripe، والبوابة الخليجية النشطة):

| السيناريو | النتيجة المتوقعة | Stripe | خليجية |
|---|---|---|---|
| دفع ناجح | الطلب `CONFIRMED`/`PAID`، المخزون الفعلي انخفض، `reservedStock` عاد للصفر، وصل بريد التأكيد | [ ] | [ ] |
| بطاقة مرفوضة | الطلب `FAILED`، المخزون المحجوز عاد متاحاً | [ ] | [ ] |
| إغلاق صفحة الدفع/إلغاء | صفحة `checkout/cancel`، والحجز يتحرر (فوراً أو بعد الانتهاء) | [ ] | [ ] |
| إعادة إرسال نفس الـ Webhook (Idempotency) | لا خصم مخزون مزدوج، **ولا بريد ثانٍ** | [ ] | [ ] |
| Webhook بتوقيع خاطئ | يُرفض (400/401) ولا يغيّر شيئاً | [ ] | [ ] |
| نقر مزدوج سريع على "إتمام الطلب" | لا يُنشأ طلبان ولا يتضاعف الحجز | [ ] | [ ] |
| آخر قطعة في المخزون بحسابين متزامنين | أحدهما ينجح والآخر يُرفض، بلا بيع زائد | [ ] | [ ] |

- [ ] **انتهاء الطلب المعلّق:** أنشئ طلباً ولا تدفع، عدّل `createdAt` إلى قبل 61 دقيقة (Prisma Studio)، ثم استدعِ المهمة يدوياً:
  ```powershell
  curl.exe -H "Authorization: Bearer <CRON_SECRET>" -H "x-vercel-protection-bypass: <SECRET>" https://staging.your-domain.com/api/cron/expire-orders
  ```
  المتوقع: الطلب `FAILED` والمخزون المحجوز محرَّر، ولا يتأثر أي طلب أحدث من 60 دقيقة
- [ ] استدعاء المهمة بدون سر أو بسر خاطئ يُرفض

## F. دورة حياة الطلب (لوحة الإدارة)
- [ ] `CONFIRMED → PROCESSING → SHIPPED → DELIVERED` تعمل، وتظهر أزرار الانتقالات الصالحة فقط
- [ ] لا يمكن قفز مرحلتين (مثل PENDING → SHIPPED) ولا الخروج من حالة نهائية
- [ ] إلغاء طلب مدفوع من الإدارة: يبدأ الاسترداد عبر البوابة الأصلية، ويعود المخزون، وتتحول الحالة `CANCELLED`
- [ ] **نقر مزدوج على زر الاسترداد**: استرداد واحد فقط (الثاني `409 REFUND_IN_PROGRESS`)
- [ ] مرتجع `RETURNED` مع تفعيل `restock` يزيد المخزون الفعلي، وبدونه لا يزيده
- [ ] `OrderStatusLog` يسجل كل تغيير مع الفاعل `[admin:...]`/`[customer:...]`/`[system]`
- [ ] أفتح تبويبين لنفس الطلب وأغيّر حالته من الأول ثم الثاني → الثاني يحصل على `409 ORDER_STATE_CONFLICT`

## G. بوابة العميل
- [ ] `/account/orders` تعرض طلبات العميل فقط، والتفاصيل والتتبع الزمني صحيحان
- [ ] الملاحظات الإدارية الداخلية **لا تظهر** للعميل في الخط الزمني
- [ ] إلغاء العميل لطلب `PENDING` أو `CONFIRMED` ينجح (مع استرداد إن كان مدفوعاً)، وبعد `PROCESSING` لا يظهر الزر
- [ ] فتح رابط طلب يخص عميلاً آخر → 404 (وليس 403)
- [ ] إدارة العناوين: إضافة/تعديل/حذف، وتعيين افتراضي يلغي الافتراضي السابق

## H. المراجعات والمفضلة
- [ ] تقييم منتج لم يُستلم → 403 `PURCHASE_REQUIRED`
- [ ] بعد وضع الطلب `DELIVERED` يظهر نموذج التقييم، والتقييم الثاني لنفس المنتج → 409
- [ ] المراجعة تبقى `PENDING` ولا تظهر عاماً حتى تعتمدها من `/admin/reviews`، والاسم يظهر مقنّعاً ("سالم خ.")
- [ ] رفض/حذف مراجعة يعمل ويحدّث متوسط التقييم وتوزيع النجوم
- [ ] المفضلة: إضافة/حذف فوري، لا تكرار، القلب يتلون في القوائم، ونقل عنصر للسلة يعمل
- [ ] منتج مسودة/مؤرشف لا يمكن إضافته للمفضلة

## I. البريد الإلكتروني
- [ ] بريد تأكيد الطلب يصل بالعربية للعميل العربي وبالإنجليزية للإنجليزي
- [ ] عرض RTL سليم، والجدول والمجاميع صحيحة، ورابط تتبع الطلب يعمل للمسجلين
- [ ] يظهر جيداً في Gmail وOutlook وتطبيق البريد على الجوال (وليس في spam)
- [ ] طلب زائر (Guest) يصل لبريده

## J. لوحة الإدارة والتقارير
- [ ] مؤشرات KPIs تطابق العدّ اليدوي، والإيرادات مفصلة بالعملات بلا خلط بين عملتين
- [ ] الطلبات الملغاة/المرتجعة/الفاشلة **مستثناة** من الإيرادات
- [ ] تنبيهات المخزون المنخفض تحسب `stock − reservedStock`
- [ ] CRUD المنتجات والفئات كامل، مع الصور والمتغيرات والفئات الهرمية

## K. اللغة والمظهر والأجهزة
- [ ] تبديل عربي/إنجليزي فوري، مع RTL/LTR صحيح وبلا نصوص غير مترجمة أو مقلوبة
- [ ] الوضع الداكن والفاتح: لا نص غير مقروء
- [ ] الأجهزة: iPhone Safari، Android Chrome، Desktop Chrome/Safari/Firefox، وشاشة صغيرة (360px)
- [ ] سلة/Checkout/الدفع قابلة للاستخدام بالكامل على الجوال بيد واحدة

## L. الأداء وSEO
- [ ] Lighthouse (جوال) على الرئيسية وصفحة منتج وقائمة المنتجات: Performance ≥ 80، SEO ≥ 90، Accessibility ≥ 90
- [ ] صفحة منتج تحتوي JSON-LD صالحاً (اختبره في Rich Results Test)
- [ ] `/sitemap.xml` و `/robots.txt` صحيحان (robots يمنع `/admin` و`/api`)

## M. الأمان (فحوص يدوية سريعة)
- [ ] تعديل السعر/الخصم في طلب الشبكة (DevTools) لا يؤثر على المبلغ المحصّل (يُعاد حسابه بالخادم)
- [ ] محاولة استخدام `addressId` لمستخدم آخر عند الدفع تُرفض
- [ ] أخطاء الـ API لا تكشف Stack أو أسماء جداول أو مسارات ملفات
- [ ] `npx tsx scripts/smoke-test.ts ...` بدون أي فشل
